# TG Stats — локальный анализатор переписки Telegram

Дашборд со статистикой переписки Telegram: графики, тепловые карты, календарь активности, анализ разговоров, медиа-галерея и экспорт красивого отчёта.

**🔒 Приватность:** всё считается в вашем браузере. Файл переписки и медиа **никуда не загружаются**: в продакшн-сборке стоит Content-Security-Policy `connect-src 'self'`, которая запрещает странице отправлять данные на внешние серверы. Сайт можно открыть и без интернета после первой загрузки.

## Как пользоваться

1. В **Telegram Desktop** откройте чат → **⋮** → **«Экспорт истории чата»**.
2. Отметьте нужные медиа и выберите формат **«Машиночитаемый JSON»** (HTML тоже поддерживается, но в нём меньше данных).
3. Откройте сайт и перетащите папку `ChatExport_…` целиком (или `result.json` / `messages.html` / ZIP-архив).

Экспорт всего аккаунта (**Настройки → Продвинутые → Экспорт данных из Telegram**) тоже подходит — после загрузки появится список чатов.

## Что считается

| Раздел | Содержимое |
|---|---|
| **Обзор** | ключевые числа, доли участников, достоверность, факты, профиль-радар, таблица сравнения из 40+ метрик |
| **Время** | сообщения по дням/неделям/месяцам/годам, тепловая карта день×час, календарь по годам, часы, дни недели, сезонность, накопительный график, серии, самое долгое молчание, топ дней |
| **Диалоги** | кто начинает разговор (с погрешностью), первый контакт за день, последнее слово, попытки без ответа, отложенные ответы, «как дела?», индекс вовлечённости, время ответа (медиана, распределение, по часам, по месяцам), длительность разговоров, список всех разговоров с объяснением решения |
| **Текст** | облако слов, любимые слова и фразы, эмодзи, реакции и кто кому их ставит, кто кому отвечает, длина сообщений, стиль (вопросы, смех, нежность, скобочки, мат, капс), тональность по месяцам, ссылки, хештеги, упоминания, пересылки |
| **Медиа** | фото, видео, кружки, голосовые, стикеры, GIF, файлы, звонки; галерея с просмотрщиком, плеер голосовых, любимые стикеры |
| **Чат** | просмотр переписки с поиском, фильтрами и переходом к дате |
| **Точность** | погрешность каждой метрики, методика, распределение пауз, устойчивость к порогу |

Экспорт: **HTML-отчёт** (автономный файл с графиками), **печать в PDF**, **JSON** со всей статистикой, **CSV** участников и сообщений (открывается в Excel), **PNG** любого графика.

## Как определяется, кто начинает разговор

Наивный подсчёт «кто первым написал после полуночи» или «после паузы» ошибается: часто первым после паузы пишет тот, кто **отвечает** на вчерашний вопрос. Алгоритм ([`src/core/conversations.ts`](src/core/conversations.ts)):

1. **Порог паузы подбирается под переписку.** Логарифмы пауз между сообщениями описываются смесью двух нормальных распределений (EM): «внутри разговора» и «между разговорами». Порог — точка равной вероятности.
2. **Короткие разрывы склеиваются.** Пауза меньше 2.5× порога без приветствия или звонка — продолжение того же разговора.
3. **Каждое начало оценивается по контексту.** Вероятность настоящей инициативы растёт от длины паузы, приветствий, вопросов «как дела / что делаешь», звонка, повторного сообщения без ответа. Она падает, если сообщение — reply на сообщение собеседника, прошлый разговор закончился вопросом собеседника или есть извинение за задержку («сорри, был занят»).
4. **Инициатива делится по вероятности**: открывший получает *p*, автор неотвеченного сообщения получает *1 − p*.
5. **Погрешность** (95%) = неопределённость классификации (Σp(1−p)/N²) + ошибка выборки (S(1−S)/N) + чувствительность к порогу (разброс при ×0.5 и ×2).

На синтетической переписке с известной истиной алгоритм верно определяет инициатора в **~95%** разговоров. Наивный подсчёт даёт ~84%. Это проверяется в тесте `src/core/core.test.ts`.

«Первый контакт за день» считается от **ночного затишья**, а не от полуночи. Час затишья определяется по самой переписке.

## Разработка

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # тесты парсеров и алгоритма
npm run build    # сборка в dist/
```

Стек: React 19, TypeScript, Vite, [Glisse](https://glisse.kelvinzhang.ca) (Liquid Glass UI: TabBar, SegmentedControl, Switch, Slider, Menu, SearchField), ECharts + echarts-wordcloud, JSZip, TanStack Virtual. Разбор JSON и вся аналитика выполняются в Web Worker, поэтому интерфейс не зависает даже на сотнях тысяч сообщений.

### Структура

```
src/core/        парсеры JSON/HTML, загрузчик папок/ZIP, аналитика, алгоритм разговоров, демо-генератор
src/worker/      Web Worker
src/ui/          дашборд, вкладки, графики, медиа-просмотрщик, экспорт отчёта
```

## Хостинг

- **GitHub Pages**: workflow `.github/workflows/deploy.yml` собирает и публикует сайт при каждом push в `main`.
- **Cloudflare Pages**: подключите репозиторий, build command `npm run build`, output `dist`. Пути относительные (`base: './'`), поэтому сайт работает и в корне, и в подпапке.
